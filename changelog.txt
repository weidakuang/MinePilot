0.1.9-dev-mc26.2
-----------------
- Add a narrowly observation-bound recovery for explicit food tasks. If a
  verified model response is speech-only, the brain may recover only the
  current visible dropped food pickup or owned-food consumption stage; it
  never invents a target, route, item count or general skill.
- Add regressions for the golden-apple pickup and consumption paths, including
  the honest model audit event and normal SkillSupervisor lease.

  headless ServerPlayer combat/parkour slices. Provider, rendered-client,
  Hardcore and M0-M4 gates remain `NOT_RUN`.

0.1.8-dev-mc26.2
-----------------
- Add an observation-bound wood/tree gathering handoff. Explicit player
  requests such as “帮我砍点树” or “chop some wood” expose only
  `gather_visible_block_cluster` when a fair first-person ray already sees a
  complete log/wood/stem surface; otherwise the model must refresh or survey.
  The model still chooses the exact seed, block type, bounded size, radius and
  tool, while the vanilla skill revalidates every connected block and drop.
- Make planner skill-schema handoffs an explicit ordered pipeline so adding a
  narrow action cannot accidentally reintroduce phase-retired skills.
- This remains a verification build: focused JVM contracts and Forge
  65.1.1 no-model physical slices pass, while provider, rendered-client,
  Hardcore and M0–M4 gates remain `NOT_RUN`.

0.1.7-dev-mc26.2
-----------------
- Narrow server-bound “follow me” planning to the one fair next action: an
  observed speaking player exposes only `follow_entity`; an out-of-view
  player exposes only a bounded first-person reacquisition survey. A premature
  model `COMPLETE_GOAL` for that same visible bound player now starts the
  ordinary follow skill instead of announcing completion or leaving the body
  waiting.
- Narrow explicit, unambiguous visible dropped-item pickup requests to
  `collect_observed_item`. The guard recognises an exact registry/name match,
  common log wording, or a single deictic fair drop; multiple possible drops
  retain the broader schema rather than guessing.
- Keep this an engineering verification build: the focused JVM contracts and
  no-model physical ServerPlayer follow slice passed, but live-provider,
  rendered-client, Hardcore and M0–M4 gates remain `NOT_RUN`.

0.1.6-dev-mc26.2
-----------------
- Fix a production planner-data mismatch: semantic entity metadata is exposed
  as `properties`, while the immediate follow and visible-item prompts had
  incorrectly instructed the model to read `visibleProperties`. This could
  make a real provider miss the visible player or dropped item despite a
  valid fair observation.
- Add an observation-bound two-stage food handoff for an explicit "I gave you
  a golden apple; eat it" request: visible item -> normal vanilla pickup ->
  verified owned-stack consumption. The model still chooses the allowed skill;
  the server now rejects a premature `COMPLETE_GOAL` after pickup. Natural
  follow-up phrasing such as "then eat it now" preserves the named-food goal
  instead of replacing it with an ambiguous new action.
- Ground erroneous "just a pile of stones" chat claims against current
  first-person terrain cues without pretending to know an unseen canyon or
  cave boundary.
- Keep the cross-platform verified credential status mapping introduced in
  this development line: macOS Keychain, Windows DPAPI and Linux Secret
  Service are reported honestly without exposing a key.
- Focused JDK25 tests cover the prompt/schema contract, food handoff and
  completion guard, and terrain grounding. Formal live-model/client,
  Hardcore and M0--M4 gates remain NOT_RUN until an authorized Linux/Xvfb
  environment runs them.
